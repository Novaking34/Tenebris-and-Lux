== Abstract & Engineering Intent

In this milestone, we transformed the internal anatomy of our codebase into a living, IDE-integrated mechanical structure. Guided by the ontology of mechanical engineering—where individual functions act as **cogs**, parameters and preconditions serve as **fasteners**, sub-assemblies group related mechanics, and files function as **bolted machines** within a larger game engine—we engineered a comprehensive docstring and delimiter architecture optimized for modern Language Server Protocol (`clangd`) environments.

Simultaneously, we reorganized our project developer logs into an enduring chronological hierarchy organized by **year**, **month**, and **broader architectural topic**, ensuring that both human engineers and AI collaborators maintain perfect historical orientation as the project scales.

---

== 1. The Need for IDE-First Hover Documentation

Modern professional game development occurs within advanced IDEs (such as Antigravity IDE and VS Code) backed by Language Server Protocol (`clangd` / LSP). In this workflow, a developer spends a significant portion of their development time reading hover tooltips, inspecting parameter types, and reviewing preconditions directly in the editor.

Prior to this refactor, hovering over a function such as `math_clamp_int` revealed basic type signatures or truncated comments. Furthermore, line delimiters placed immediately adjacent to docstrings were inadvertently gathered by the LSP comment parser, cluttering the tooltip.

### 1.1 The Clangd Hover Contract

To produce clean, beautiful, and informative hover windows in the IDE:
1. **Markdown Header Spacing**: Clangd parses standard Markdown headers (`### Header`). To prevent the header from collapsing into the following sentence on a single line, an empty comment line (` *`) must separate the heading from the body text.
2. **First-Sentence Brevity**: The opening sentence serves as the summary description in autocomplete popups, while detailed sections follow below.
3. **Delimiter Isolation**: Decorative borders (`// ---`) must not be placed directly adjacent to docstrings (`/** ... */`) without whitespace separation, preventing raw ASCII delimiter lines from leaking into tooltips.
4. **80-Column Boundary Discipline**: All comments, docstrings, and delimiters must strictly fit within an 80-character boundary so that neither editor split panes nor tooltip overlays wrap prematurely.

== 2. The Machine Metaphor: From Cosmos to Fasteners

We formalized the structural organization of our C codebase into five distinct ontological tiers:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        COSMOS: TENEBRIS AND LUX                        │
│                 (The Complete Tactical Strategy RPG)                   │
├────────────────────────────────────────────────────────────────────────┤
│                     STRATUM: ARCHITECTURAL LAYER                       │
│    Layer 0: Core Utilities | Layer 1: Simulation Engine | Layer 2: GUI │
├────────────────────────────────────────────────────────────────────────┤
│                       MACHINE: SUBSYSTEM MODULE                        │
│    e.g. core.util.math | core.util.geom | core.util.string | time      │
├────────────────────────────────────────────────────────────────────────┤
│                  ASSEMBLY: SUB-CATEGORY / FUNCTION GROUP               │
│    e.g. [ SUB-ASSEMBLY 3.1: INTEGER CLAMPING & SATURATION COGS ]      │
├────────────────────────────────────────────────────────────────────────┤
│                        COG: INDIVIDUAL FUNCTION                        │
│    e.g. math_clamp_int() | geom_rect_intersects() | str_safe_copy()   │
├────────────────────────────────────────────────────────────────────────┤
│                   FASTENERS: NUTS, BOLTS & TRIPWIRES                   │
│    Invariants, Preconditions, Clamping Floors, Return Error Codes      │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Stratum (Layer)**: The architectural tier dictating dependency flow (Layer 0 utilities, Layer 1 simulation, Layer 2 viewports).
2. **Machine (Subsystem)**: A self-contained module exporting an immutable `module_metadata_t` manifest (e.g. `core.util.math`).
3. **Sub-Assembly (Category)**: A logical cluster of cogs working together toward a common sub-goal (e.g. *Integer Clamping & Saturation*, *Equilibrium Steering*, *AABB Hit-Testing*).
4. **Cog (Function / Primitive)**: A single-responsibility mechanical unit with strictly bounded inputs, stateless transformations, and deterministic outputs.
5. **Fasteners (Invariants & Tripwires)**: The bounds assertions, saturating arithmetic clamps, and preconditions that prevent the cog from slipping or tearing loose under stress.

== 3. Visual Border & Delimiter Standards

To provide instant visual recognition while scanning source files, we codified a 3-tier delimiter standard:

* **Level 1: Block Lifecycle Banner** (80 columns, double equal border `==`):
+
[source,c]
----
// =============================================================================
// BLOCK 3: BODY BLOCK
// Stratum: Layer 0 (Core Utilities) | Machine: Bounded Arithmetic Engine
// =============================================================================
----
* **Level 2: Sub-Assembly Banner** (80 columns, single dash border `--`):
+
[source,c]
----
// -----------------------------------------------------------------------------
// [ SUB-ASSEMBLY 3.1: INTEGER CLAMPING & SATURATION COGS ]
// Mission: Guardrail calculations against integer overflow and underflow.
// -----------------------------------------------------------------------------
----
* **Level 3: Isolated Cog Docstring**:
+
[source,c]
----
/**
 * Clamps a signed integer to a closed interval [min_val, max_val].
 *
 * ### Machine Role & Mission
 *
 * Serves as a foundational mathematical guardrail preventing overflow,
 * underflow, or boundary corruption across player statistics, resonance
 * meters, and moral sway values. If min_val > max_val, boundaries swap.
 *
 * ### Ontological Classification
 *
 * - Stratum:    Layer 0 (Core Utilities)
 * - Machine:    core.util.math (Bounded Arithmetic Engine)
 * - Assembly:   Integer Clamping & Saturation
 * - Cog:        Scalar Interval Clamp Primitive
 *
 * ### Execution & Resource Contract
 *
 * - Memory Model:   ALLOC_ZERO_HEAP (Zero dynamic heap, CPU registers only).
 * - Concurrency:    REENTRANT_PURE (Stateless, deterministic, thread-safe).
 * - Latency Budget: < 1 microsecond execution time (O(1) branching).
 *
 * @param[in] val     The raw input integer to evaluate.
 * @param[in] min_val Lower boundary limit (inclusive).
 * @param[in] max_val Upper boundary limit (inclusive).
 *
 * @return Clamped value satisfying `min_val <= result <= max_val`.
 *
 * @pre  `min_val <= max_val` under normal operation.
 * @post Result resides strictly within `[min_val, max_val]`.
 *
 * @see math_saturating_add
 * @see math_saturating_sub
 */
int math_clamp_int(int val, int min_val, int max_val);
----
