== 1. Architectural Motivation & The Problem of Blind Mutation

In complex tactical TRPG simulations featuring moral sway continuums, dual-relic resonance
conservation, and branching multi-path endings, diagnosing subtle emergent phenomena
(such as state desynchronization, illegal stance shifts, or drift in moral alignment)
via standard print statements is inherently flawed:

1. **Destructive Mutation**: Once a turn completes, state is mutated in-place. If an
   invariant tripwire trips on turn 15, the precise historical trajectory that produced the
   anomaly is irretrievably lost.
2. **Layer Coupling Risks**: A debugger built directly inside Layer 1 risks coupling
   presentation, inspection, and simulation logic together, breaking the strict unidirectional
   strata of the engine.
3. **Dynamic Memory Vulnerability**: Conventional debuggers allocate heap memory for event
   queues and dynamic snapshots, introducing fragmentation and memory leaks that violate
   our embedded C11 zero-heap discipline (`ALLOC_ZERO_HEAP`).

To solve these challenges, we designed a zero-heap, decoupled state debugger in Layer 0
complemented by simulation adapters in Layer 1 and presentation controls in Layer 3.

== 2. Decoupled State Snapshot Ring Buffer Architecture

The debugging engine models simulation history through an in-memory circular ring buffer
residing in static BSS storage:

=== Strict Decoupling Invariant

Layer 0 never includes Layer 1 simulation headers (`sim/sim_types.h` or `sim/game.h`).
Instead:
- `debug_state_fields_t` declares pure ISO C11 primitive fields.
- Layer 1 (`src/sim/game.c`) implements bidirectional projection adapters:
  * `game_state_to_debug_fields()` maps `player_state_t` into `debug_state_fields_t`.
  * `game_state_from_debug_fields()` reconstructs `player_state_t` from `debug_state_fields_t`.
  * `game_record_debug_snapshot()` captures turn-boundary snapshots.
  * `game_rewind_debug_snapshot()` safely rewinds the live player simulation.

== 3. Dynamic Breakpoints & Differential State Analysis

=== Multi-Condition Breakpoint Engine

Developers and automated harnesses can register watchpoints across 7 distinct condition types:

1. `DEBUG_BREAK_TURN`: Triggers upon reaching a specific turn count.
2. `DEBUG_BREAK_STANCE`: Triggers when combat stance shifts to a target stance ID.
3. `DEBUG_BREAK_SWAY_RANGE`: Triggers when absolute moral sway breaches a threshold.
4. `DEBUG_BREAK_RESONANCE_BREACH`: Triggers if Lux or Tenebris resonance exceeds limits.
5. `DEBUG_BREAK_HP_THRESHOLD`: Triggers when HP drops below a critical floor.
6. `DEBUG_BREAK_LOCATION`: Triggers upon journeying into a designated province.
7. `DEBUG_BREAK_TRIPWIRE`: Triggers when any subsystem trips a latched diagnostic wire.

=== State Differential Analysis (`debug_diff_snapshots`)

Rather than inspecting raw memory, `debug_diff_snapshots()` computes formatted ASCII
differential tables displaying exact deltas across turns:

== 4. Data-Driven Debugger Profiles & Fallback Monoliths

Following the data-driven architecture of `data/manifest.json`, the debugger catalog
is maintained under `data/debug/`:

* `data/debug/manifest.json`: Central catalog defining available profiles (`default`,
  `strict`, `trace`) and active default pointer.
* `data/debug/default.json`: Balanced profile (64 snapshots, tripwire traps enabled,
  1-turn snapshot intervals, interactive REPL active).
* `data/debug/strict.json`: Strict validation profile (break-on-error, break-on-stance-change,
  rigid state boundary verification).
* `data/debug/trace.json`: Fine-grained telemetry profile for deep engine debugging.
* `src/util/debug/debug_fallback.c`: Quarantined emergency fallback code page guaranteeing
  operational readiness even if external JSON assets are missing or corrupted.
