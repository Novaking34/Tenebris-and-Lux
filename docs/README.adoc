[[five-block-adoc-standard]]
== Organizing AsciiDoc Like Source Code (5-Block Standard)

Just as every `.c`, `.h`, `.json`, and `.cmake` file separates metadata, opening contracts, body logic, audits, and closing navigation, new AsciiDoc documents use native AsciiDoc comments so metadata stays invisible in rendered HTML/PDF/Markdown output while remaining readable in source:

* **Block Banners (`BLOCK 1` .. `BLOCK 5`)**: Enclosed inside native AsciiDoc block fences (`////` ... `////`). Placing `BLOCK 1` immediately above line `= Document Title` keeps Asciidoctor title, author, revision, and `:toc:` parsing 100% valid.
* **Sub-Assembly Dividers**: Use single-line comments (`// --- Sub-Assembly X.Y: Description ---`) inside `BLOCK 2` through `BLOCK 5`.
* **Rich Textbook Constructs**: Prefer `[NOTE]`/`[TIP]`/`[IMPORTANT]`/`[WARNING]` delimited blocks (`====`), `****` designer/engineer callout sidebars, `[source,<lang>,linenums,start=N]` code blocks with `// <1>` callouts, `a|` rich table cells, `[qanda]` checkpoints, and `include::../snapshots/<id>.adoc[]` plates.

// --- Sub-Assembly 4.1: Publishing & Validation Audit Commands ---
== Verification & Publishing Checkpoints

Before committing updates to documentation, snapshot manifests, or PDF theme specifications, run the native toolchain checks from repository root:

[source,bash]
----
# 1. Extract all code snapshot plates into docs/snapshots/
cargo run --manifest-path tools/Cargo.toml --bin master_guide -- --snapshots

# 2. Rebuild all 6 Volumes + MASTER_GUIDE (.adoc, .md, .pdf)
cargo run --manifest-path tools/Cargo.toml --bin master_guide -- --all

# 3. Validate standalone AsciiDoc files with strict warning checks
asciidoctor --failure-level=WARN -o /dev/null docs/README.adoc docs/architecture/*.adoc

# 4. Run repository schema & engine/game unit verification
./tools/target/debug/tl_tools validate all && ctest --test-dir build --output-on-failure
----

[qanda]
Why keep Block 1..5 comments in `.adoc` files if HTML and PDF hide them?::
  They give both human authors and AI agents an unmistakable structural spine inside raw `.adoc` source files without leaking boilerplate banners into rendered books or Markdown exports.
Can non-programmers update documentation safely?::
  Yes. Narrative chapters live cleanly in `BLOCK 3`, formatting themes live in readable JSON (`docs/guide_theme_config.json`), and live code listings update automatically via `--snapshots` whenever C or Rust code shifts.
